# 레디보드

PMO가 인력계획서와 메일 요청을 확인해 명단을 관리하고, 수행사 직원이 개인 초대 링크에서 등록을 마친 뒤 계정·출입, 교육, 서류를 준비하는 웹서비스입니다. 우리금융그룹 참고 이미지의 파란 메뉴·헤더, 흰 작업 영역과 캐릭터 디자인을 유지합니다.

주관사 전체 현황은 **단계별 인원**, 수행사 홈은 **준비 로드맵과 지금 내가 할 일**을 보여줍니다. 등록·필수 준비·최종 확인·실제 투입 상태를 구분하고, 요약 수치에서 필터 목록으로 연결합니다. [화면 전후 변경·검증 경로](docs/UI-업무중심-개편.md)를 참고하세요.

주관사의 **준비 작업**에서는 투입·수행·철수 단계별 세부 업무를 펼쳐 인원을 선택하고, 기안 첨부용 예시 엑셀을 미리보기·다운로드할 수 있습니다. [업무 절차·양식·검증 안내](docs/기안첨부-일괄양식.md)를 참고하세요.

전체 현황은 **전체 투입 준비·기안 작성·교육·투입 필수 서류**의 완료율과 `완료 인원 / 총인원`을 보여줍니다. 계정 신청 6종은 전원 필수이며, 기안 완료는 별도 기록합니다. 카드를 누르면 해당 미완료 명단으로 이동합니다. 수행사 홈에서는 로드맵을 눌러 팝업으로 상세를 확인하고, 아래 2열에서 본인 작업과 주관사 준비를 구분합니다. 교육·서류는 **나의 작업** 하위 메뉴에서 확인합니다. [완료율·화면 개편 안내](docs/완료율-로드맵-개편.md)

## HTML 단독 시연 — 서버 실행 불필요

[HTML](preview/readyboard-offline.html) 또는 [ZIP](preview/readyboard-offline.zip)을 내려받아 Chrome/Edge에서 HTML을 열면 됩니다. 상단에서 PMO·SFA 담당자·그룹웨어 담당자·수행사와 수행사 인원을 전환하세요.

엑셀 불러오기, 본인 등록, 초대 링크, 작업 처리·추가, 서류 작성·제출·승인, 수료증 원본, ZIP·엑셀 다운로드, 문의·알림, 메일 검토가 이 브라우저에서 동작합니다. 명단·파일·초대·검토 이력은 IndexedDB에 저장되어 새로고침해도 남습니다. 초대 링크는 발급한 HTML과 같은 브라우저에서 여세요. 상단 **시연 백업 / 백업 불러오기**로 파일 원본까지 옮길 수 있습니다.

외부 메일·AI·본인확인·Dooray 전송은 가상 시연이며 실제 외부 서비스를 호출하지 않습니다. 역할 전환은 시연을 위한 기능입니다. 전체 흐름과 검증은 [HTML 단독 시연 안내](docs/HTML-단독시연-구현.md)를 참고하세요.

소스에서 다시 만들 때는 `npm ci` 후 `npm run export:html`을 실행합니다. 만들어진 HTML을 사용하는 사람은 Node.js나 서버가 필요하지 않습니다.

## Vercel 배포

저장소의 `vercel.json`이 **`npm run build:offline` → `dist/index.html`**을 배포합니다. Vercel에서는 별도 API/DB 없이 브라우저 저장 방식의 시연이 열립니다. 빌드는 최신 소스와 합성 초기 명단으로 단일 HTML을 생성하며 API 서버·SQLite를 실행하지 않습니다. `/api/session` 호출로 시작하던 서버형 Vite 빌드를 Vercel 배포에 사용하지 않습니다.

Git 연동 Production Branch가 `master`인지 확인하고 새 커밋의 배포가 **Ready**가 되면 **Visit** 또는 프로젝트의 Production Domain으로 여세요. `...-50vyqscy8-...vercel.app`처럼 배포별 주소는 이전 결과를 계속 가리킬 수 있으므로 새 배포 주소를 사용합니다. 화면 상단에 HTML 단독 시연과 빌드 버전이 표시됩니다.

로컬 배포 산출물 검증:

```bash
npm run build:offline
npm run test:deployment
```

## 서버형 서비스 실행

**Node.js 22.13 이상**이 필요합니다. 이번 검증은 Node.js 24.22.1에서 진행했습니다. React 19/Vite 7, ExcelJS와 Node HTTP 서버, 내장 SQLite를 사용합니다.

Git Bash에서 저장소 폴더로 이동한 다음 실행합니다.

```bash
npm ci
cp .env.example .env
# .env의 ADMIN_PASSWORD를 원하는 관리자 비밀번호로 변경
npm run dev
```

`http://localhost:5173`에 접속해 PMO와 설정한 비밀번호로 로그인합니다. 개발 명령 하나가 Vite(5173)와 API 서버(3001)를 함께 실행합니다. PMO 화면의 **인원 명단 → 인력계획서 불러오기**에서 시작하세요.

빌드한 서비스는 API 서버가 함께 제공합니다. 이 방식은 실행 시 Rollup 네이티브 모듈을 로드하지 않습니다.

```bash
npm run build
npm start
# http://localhost:3001
```

`npm run preview`와 `npm run preview:static`도 빌드와 API를 함께 제공하도록 되어 있습니다. `.env` 설정이 필요합니다. 다른 PC에서는 서버에 도달할 수 있는 주소를 사용해야 합니다. 공유 시 `API_HOST=0.0.0.0`, `PUBLIC_BASE_URL=https://실제서비스주소`를 설정하고 해당 주소로 접속하세요. HTTPS 서비스라면 `SECURE_COOKIES=true`를 설정합니다. 개발 포트로 공유한다면 `PUBLIC_BASE_URL`도 개발 서버의 외부 주소로 맞춥니다.

## 사용 흐름

1. PMO 로그인 → 인원 명단 → 프로젝트 선택 → `.xlsx` 업로드.
2. AI 또는 열 이름 기반 후보를 참고해 시트·헤더·열을 확인하고 **매핑 적용 · 미리보기**를 누릅니다.
3. 원본 시트·행과 추출값을 확인합니다. 수정·행 제외가 가능하며, 생년만 있으면 확인 대상으로 남깁니다. 중복 의심 인원은 **신규 등록 / 기존 인원 연결**을 직접 선택합니다.
4. 확정한 행을 **본인 등록 대기**로 저장합니다. 같은 파일의 같은 행을 재확정해도 인원을 다시 만들지 않습니다.
5. **개인별 초대 링크**에서 인원별 링크를 생성·복사합니다. 수행사별 이름·링크를 모아 기존 메일이나 메신저로 전달할 수 있습니다.
6. 직원은 별도 브라우저에서 링크를 열고 연락처·예정 투입 기간·전체 생년월일을 확인해 등록합니다. 기존 UUID 기록이 **등록 완료**로 바뀌며 준비 작업이 연결됩니다.
7. PMO는 새로고침 또는 자동 조회로 변경된 상태를 확인합니다. 서류·수료증 원본도 서버에 저장해 권한이 있는 다른 브라우저에서 다운로드합니다.

예제는 [A 양식](public/examples/인력계획서_A.xlsx), [B 양식](public/examples/인력계획서_B.xlsx)을 제공합니다. B는 제목·빈 행 다음에 `업체명 / 투입인력 / 생년` 헤더가 나오며 동명이인 2명을 포함합니다.

## AI 메일 요청 검토

PMO의 **AI 메일 요청 검토** 메뉴는 먼저 **받은편지함**을 엽니다. 메일 목록과 본문을 나란히 읽고, 상단 **설정**에서 기존 수집 범위를 관리합니다. **새 메일 확인** 한 번으로 가상 메일 5통이 먼저 목록에 도착한 뒤 분석되며, 실제 투입 요청 2통에서만 초안 2건을 만듭니다. **검토 대기 N건**으로 요청을 인원별로 검토합니다. 팝업을 닫아도 검토함에서 다시 열 수 있고, 원문·기존값·제안값 확인 후 승인한 내용만 반영합니다.

기본 `MAIL_PROVIDER=mock`은 가상 메일함입니다. 연결 정보가 없는 현재 환경에서 실제 회사 메일이나 외부 AI를 호출했다고 표시하지 않습니다. `OPENAI_API_KEY`가 없으면 규칙 기반 초안을 명시합니다. 실제 연결용 IMAP 읽기 전용 어댑터와 기존 OpenAI 호환 AI 설정을 제공합니다.

- `PMO/인력요청`: 일반 메일 3통과 투입 요청 2통. 김민수 11월 23일 → 25일 변경, 이서연 11월 23일 신규 투입과 이서연에게만 개발망 계정 요청. 두 초안이 생성됩니다.
- `PMO/날짜미정검증`: 날짜 미정·조건부 요청을 확인하고 검토 보류합니다.
- `PMO/회신검증`: 김민수의 최신 보류 요청과 기존 요청 이력을 확인합니다. 인용한 이서연 요청은 다시 추출하지 않습니다.
- 준비용 [김민수 인력계획서](public/examples/메일검토_기준인력.xlsx)를 1차 경로에서 등록하고 본인 등록 투입일을 **2026-11-23**으로 설정한 뒤 시연하세요.

기존 인원 UUID·본인 등록 상태·완료 교육/서류는 유지합니다. 투입일 변경 시 미완료 작업의 개인별 마감일을 조정하고, 새 인원은 본인 등록 대기로 만들어 같은 화면에서 초대 링크를 발급합니다. 중복 수집·승인 재시도를 방지하고, 검토 중 기존값이 바뀌면 재확인을 요구합니다.

[실제 연결 설정·전체 시연 순서·검증 기록](docs/AI-메일요청-검토-구현.md)에 실제 메일·실제 AI·가상 검증의 범위를 구분해 정리했습니다.

## 저장과 권한

- 기본 DB는 `data/readyboard.sqlite`입니다. 명단·상태·원본 엑셀·제출 파일·초대·감사 이력을 SQLite에 저장합니다. 인원 UUID, 프로젝트 ID와 회사 ID를 유지합니다.
- PMO는 전체, SFA/그룹웨어 담당자는 해당 프로젝트, 수행사는 자신의 한 기록에만 접근합니다. 역할·범위는 서버 세션으로 확인합니다. 상단 PMO 드롭다운은 조회 범위를 바꾸며 다른 사용자의 세션으로 전환하지 않습니다.
- 초대는 기본 72시간입니다. 재발급·등록 완료 시 기존 링크가 종료됩니다. 링크 자체가 등록 권한이므로 해당 직원 또는 전달 담당자에게 공유합니다. 실제 신원인증·SSO는 이번 범위에 포함하지 않았습니다.
- 이전 브라우저 데이터가 있으면 **PMO → 운영 기준 → 이전 브라우저 데이터 가져오기**로 이전할 수 있습니다. 기존 식별자에서 재현 가능한 UUID를 만들어 반복 이전을 막고, 접근 가능한 IndexedDB 원본도 서버로 옮깁니다. 이전 좌석 데이터는 별도 보관하며 서비스 화면과 준비율에서는 제거합니다.
- 좌석 화면·배정 기능·관련 준비 작업은 제거했습니다. 준비율과 완료 판정은 계정·출입, 교육, 제출 서류 분류의 필수 작업을 사용합니다. 기타 추가 작업은 별도 관리합니다.

## 환경변수

필수는 `ADMIN_PASSWORD`입니다. 나머지는 [.env.example](.env.example)을 참고하세요.

| 변수                                                 | 용도 / 기본값                                                                                    |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `SFA_MANAGER_PASSWORD`, `GW_MANAGER_PASSWORD`        | 선택: 프로젝트 담당자 로그인 활성화                                                              |
| `DB_PATH`                                            | `./data/readyboard.sqlite`                                                                       |
| `API_HOST`, `API_PORT`, `WEB_PORT`                   | `127.0.0.1`, `3001`, `5173`                                                                      |
| `PUBLIC_BASE_URL`                                    | 초대 링크를 열 실제 서비스 origin                                                                |
| `INVITE_TTL_HOURS`                                   | `72`                                                                                             |
| `INVITE_ENCRYPTION_KEY`                              | 선택: 고정 비밀키. 미설정 시 DB 옆 `invitation.key` 자동 생성                                    |
| `SECURE_COOKIES`                                     | HTTPS 환경에서 `true`                                                                            |
| `SEED_DEMO`                                          | 새 DB에만 10명 예시 생성, 기본 `false`                                                           |
| `MAIL_PROVIDER`                                      | 기본 `mock`, 회사에서 IMAP 지원을 확인한 뒤 `imap` 사용                                          |
| `MAIL_IMAP_HOST`, `MAIL_IMAP_PORT`, `MAIL_IMAP_USER` | 실제 서버·TLS 포트(기본 993)·수집 계정                                                           |
| `MAIL_IMAP_PASSWORD` / `MAIL_IMAP_ACCESS_TOKEN`      | 서버 전용 앱 비밀번호 또는 OAuth 토큰                                                            |
| `MAIL_FOLDER`, `MAIL_SEARCH`, `MAIL_SINCE`           | 폴더·본문 검색어·KST 수신 시작일, UI 저장값 우선                                                 |
| `OPENAI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`          | 선택: AI 매핑·메일 분석. 인력계획서·메일 분석에 공통 사용 / 기본 OpenAI 호환 API, `gpt-4.1-mini` |

인력계획서 매핑은 AI 키가 없으면 **AI 미연결**, 호출 실패 시 **수동 지정**, 불확실한 제안은 **직접 확인 필요**로 표시합니다. 어떤 경로든 PMO 확인 후 원본 셀에서 실제 값을 읽습니다. 인력계획서 매핑 AI에는 원본 이름·회사·생년월일 대신 구조와 마스킹한 샘플만 전달합니다. 메일 분석 AI에는 검토 대상의 제목과 최신 본문을 전달하며, 이전 인용문과 전체 인원 DB는 보내지 않습니다. 교육·문서 AI 패널과 문서 본인확인은 기존 시연 기능이며, 실제 문서 판독·전자서명·Dooray 전송은 미연동입니다.

DB와 `invitation.key`를 함께 백업해야 현재 초대 링크를 계속 확인할 수 있습니다. SQLite WAL 사용 중에는 백업 API 또는 서버를 종료한 상태에서 백업하세요. `.env`, DB, 비밀키는 Git에서 제외됩니다.

## 검증

```bash
npm test
npm run test:browser
npm run build
```

브라우저 검증은 Chromium을 사용합니다. 기본 경로는 `/usr/bin/chromium`이며 다른 환경에서는 `CHROMIUM_PATH`를 지정하거나 Playwright Chromium을 설치합니다. 1차 등록과 메일 검토 테스트는 각각 별도 임시 DB·포트(5180/3011, 5181/3012)와 독립 브라우저 컨텍스트를 사용합니다.

[구현·API·검증 기록](docs/인력계획서-초대등록-구현.md), [현재 기능 요구사항](docs/PMO-인력투입관리-서비스기획안.md)에 상세 내용을 정리했습니다.

**전체 HTML 시연 내보내기**는 `npm run export:html` 또는 `npm run export:review`로 생성합니다. 기존 review/preview/tuipon HTML 경로도 같은 전체 시연으로 갱신됩니다. 검증은 `npm run test:html`입니다.

서버 연결용 화면 자산만 별도로 필요하면 `npm run export:server-html`을 사용합니다. 실제 DB·인증·외부 연결이 필요한 운영 서비스는 위 서버 실행 방법을 사용합니다.

캐릭터는 사용자가 제공한 참고 이미지를 바탕으로 만든 발표용 자산입니다. 공식 운영 서비스나 공식 양식을 의미하지 않습니다. 출처와 폰트 정보는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 참고하세요.
