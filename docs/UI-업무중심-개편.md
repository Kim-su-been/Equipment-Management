## 상태와 데이터 기준

- **등록**은 본인 정보 입력 완료 여부, **준비**는 필수 작업 충족과 최종 준비 확인, **투입**은 담당자가 기록하는 실제 상태다.
- 준비율 100%라도 O16 최종 확인이 남으면 **필수 항목 완료 · 최종 확인 대기**다. 최종 확인 완료가 실제 투입 상태를 자동 변경하지 않는다. 담당자는 인원 상세의 투입 정보 변경에서 실제 상태와 사유를 저장한다.
- 투입 임박은 투입 예정이며 준비가 미완료인 인원 중 기준일부터 기본 **7일** 이내다. 운영 기준에서 1~60일로 조정한다. 예정일 경과는 별도로 표시한다. 기한과 기준일은 날짜 단위로 계산한다.
- 요약 수치와 명단 필터가 같은 계산 함수를 사용한다. 교육·서류 검토 수치는 실제 검토 목록과 같은 증빙 상태를 집계한다. 메일 수치는 현재 조회 프로젝트의 미승인 요청을 집계한다. 메일 승인 권한은 기존 PMO 전용이다.
- 내부 ID는 실제 인원 조회에만 사용하며 화면에는 이름·소속·프로젝트를 표시한다. 이름과 코드가 같으면 반복하지 않는다. 연결되지 않은 참조는 **인원 정보 확인 필요**로 표시하고 명단·원본 계획서·백업 복구로 안내한다. 자동으로 UUID를 바꾸거나 같은 이름끼리 합치지 않는다.
- 본인 등록 대기 기록은 준비 작업을 시작하지 못한다. 기존 등록 완료 기록은 같은 ID로 작업·증빙·이력을 유지한다. 교육 수강 완료 후 수료증 보완이 요청되면 본인 작업 목록에 보완 조치를 다시 표시한다.

## 검증한 경로

- 기존 명단에서 이름·소속 표시, 동일 이름/코드 중복 제거, 연결되지 않은 참조의 복구 안내.
- 요약 수치 클릭 → 실제 조건 필터 명단, 현재 담당자 미완료 작업 → 대기 사유·선행 작업 상세.
- 기존 100% 인원의 최종 확인 대기 → 최종 준비 확인. 실제 투입 상태는 기존 값을 유지하는지 확인.
- XLSX A/B 양식 → 추출·누락/생년/동명이인 검토 → 저장·재업로드 → 개인 초대·재발급 → 동일 인원 등록 완료. 선택 인원 두 명의 초대 목록이 다른 인원을 포함하지 않는지 확인.
- 새 메일 5통 → 실제 관련 메일 2통의 초안 → 팝업 → 변경 비교·대상 확인 → 김민수 한 건만 승인. 기존 ID의 투입일만 갱신되고 미승인 신규 인원은 생성되지 않는지 확인.
- 서류 제출 v1 → 주관사 보완 요청 → 수행사 홈의 보완 바로가기 → 수정·재제출 v2 → 주관사 재검토·승인. v1 원본과 이력 보존 확인.
- 브라우저 저장·새로고침·원본 ZIP/작업 양식·백업 복원, PMO/프로젝트/본인 범위 유지.
- 데스크톱 주요 업무, 390px 좁은 화면의 가로 넘침과 메뉴 조작, 키보드 시연 설정 열기/닫기, 주요 본문 대비 4.5:1 이상 확인.

## 시연 범위

실제 메일 수신·AI 모델·Dooray 전송·법적 본인확인은 연결된 서비스가 아니며 가상/규칙 기반 결과로 표시한다. 원본 서류 작성 안내·필수 항목 검사·본인확인 코드는 시연이다. PMO의 최종 검토와 승인은 실제로 저장 상태를 바꾼다. HTML/Vercel 시연의 데이터와 원본은 브라우저 IndexedDB에 저장되며 기기 간 자동 공유하지 않는다. 별도 서버형 서비스는 기존 API/SQLite 경로를 유지한다.
