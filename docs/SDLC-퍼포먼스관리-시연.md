# SDLC 퍼포먼스 관리 시연

## 범위

기존 우리금융그룹 스타일과 투입관리 화면을 유지하고 **퍼포먼스 관리** 메뉴 하나를 추가했다. 수행사 화면에는 **나의 수행 현황**으로 표시한다. ITGS의 자료가 그룹웨어를 통해 전달된 상황을 가정한 **가상 응답 데이터**를 사용한다. 실제 그룹웨어·ITGS API나 AI 모델은 호출하지 않는다.

## 사용 순서

1. 주관사에서 **퍼포먼스 관리**를 연다. 첫 진입에는 저장 전 가상 표본을 미리 보여준다.
2. **가상 자료 불러오기**를 누르면 표본을 저장한다. 같은 자료를 다시 수집해도 원천 요청 ID 기준으로 갱신해 중복 생성하지 않는다.
3. 프로젝트·운영 업무(SFA, 그룹웨어, AO 개발팀), 인원, 요청 유형, 기간을 선택한다.
4. 요약 지표의 근거 보기, SDLC 단계 팝업, 인원별 그래프와 요청 원문·단계 이력을 확인한다.
5. **현재 범위 엑셀**로 업무 근거·인원별 지표·단계 이력·산정 기준을 내려받는다.

프로젝트 표본은 현재 등록 완료된 기존 인원의 고유 ID에 연결한다. 인원마다 가상 요청 8건을 제공하며, 지연·기한 누락·재작업 패턴은 인원별로 다르다. AO 개발팀은 이 탭에서 사용하는 가상 인원 4명을 별도 제공한다. AO 인원을 기존 투입 명단에 자동 등록하지 않는다. 기존 명단·계정·교육·서류 상태는 변경하지 않는다.

## 전체 현황의 그룹별 인원 비교

전체 현황의 첫 그래프에서 SFA·그룹웨어·AO 개발팀을 한 영역에 나란히 표시한다. 모든 그룹은 같은 눈금을 사용하고, 기본값은 납기 준수율이다. 처리 현황·진행 중 지연·처리기간 중앙값·재작업률로 전환하고 그룹 내 이름순/값 정렬을 선택할 수 있다. 처리 현황은 기한 내 완료·지연 완료·기한 미등록·일반 진행·진행 지연을 중복 없이 누적 막대로 표시한다.

상단 조회 필터를 그대로 적용하고, 활동이 없는 인원도 비교 대상에 남겨 0 또는 표본 없음(`—`)으로 표시한다. 인원별 분모와 제외 건수를 함께 제공하며 인원을 누르면 기존 개인 지표·근거 업무 팝업을 연다. 프로젝트 담당자는 담당 그룹만 보며, 수행사 직원에게는 타인 비교판을 표시하지 않는다. 좁은 화면에서는 그룹을 세로로 배치한다.

## 지표 정의

| 지표            | 기준                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------- |
| 완료 처리       | 선택 기간에 완료한 요청 수. 취소 제외                                                     |
| 납기 준수율     | 기간 내 완료되고 약속 완료일이 있는 요청 중 기한 내 완료한 비율. 기한 누락 제외 건수 표시 |
| 진행 중 지연    | 종료일 현재 미완료이고 약속 완료일이 지난 요청 수. 완료 지연과 구분                       |
| 처리기간 중앙값 | 완료일 - 접수일. 달력일 기준                                                              |
| 단계별 소요기간 | 완료 요청의 동일 단계 방문 기간을 합산한 후 요청별 중앙값 계산. 대기 포함                 |
| 재작업률        | 검증에서 개발로 돌아간 이력이 있는 완료 요청 / 전체 완료 요청                             |

완료 지표는 완료일, 진행 지표는 조회 종료일 현재 상태를 기준으로 한다. 이전 종료일을 조회하면 이후 단계 변경·완료·취소 이력은 반영하지 않는다. 분모가 없으면 `—`로 표시한다. 최근 4주 그래프는 선택 범위 안의 완료 요청을 주별로 집계한다. 목록 검색·상태 필터는 상단 집계를 바꾸지 않으며, 엑셀은 상단 공통 필터의 전체 범위를 내보낸다.

기준일은 **2026-11-26로 고정된 시연 표본**이다. 실제 작업시간·영업일 계산이나 난이도 보정, 다중 담당자의 기여도 계산, 자동 등급·재계약 평가·블랙리스트 기능은 포함하지 않는다. 대기 사유는 가상 원천에 명시된 내용을 표시하며 추론하지 않는다.

## 저장·권한

- HTML/Vercel 시연: 기존 IndexedDB 작업 공간에 저장하며 새로고침·백업·복원 경로를 공유한다.
- 서버형: 기존 SQLite 저장 경로의 앱 상태에 수행 표본을 저장한다. 읽기와 수집은 같은 공통 함수를 사용한다.
- PMO: 프로젝트와 AO 표본 전체 조회·수집.
- 프로젝트 담당자: 해당 프로젝트의 표본만 조회·수집. 다른 범위의 저장 자료를 변경하지 않는다.
- 수행사 직원: 본인 ID와 연결된 업무만 조회·다운로드. 다른 인원 목록과 수집 버튼을 제공하지 않으며 API에서도 수집을 거절한다.
- 기존 데이터에 수행 표본이 없어도 열리며, 일반 준비 작업 변경으로 저장된 수행 자료가 지워지지 않는다.

## 실행과 검증

```bash
npm test
npm run build:offline
npm run test:performance
npm run test:work-ux
npm run test:browser
npm run test:html
```

전용 검증은 지표의 분모·기한 누락·취소·과거 조회·단계 재진입·동일 자료 재수집·기존 인원 보존·프로젝트/본인 권한·엑셀을 확인한다. 브라우저에서는 가상 수집과 재수집, 새로고침 유지, 개인·단계·요청 팝업, AO 필터와 실제 XLSX, 기간 오류, 모바일 조작을 확인한다.

실제 ITGS 연결 시에는 가상 응답 생성기를 실제 제공자의 조회 어댑터로 교체하고, 원천 식별자·상태·담당자·약속 완료일·단계 변경 이력을 검증해 현재 표준 구조에 매핑해야 한다. 실제 양식과 제공 항목은 아직 확인되지 않았다.
